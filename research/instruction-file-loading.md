# Come Claude Code e Codex caricano i file di istruzioni

Ricerca per COINE-139 (mappa COINE-138). Data: 2026-10-08.

Domanda di fondo: la progressive disclosure fa risparmiare token solo se il runtime carica i file secondari **quando servono** e non all'avvio. Questo documento dice, per ciascun meccanismo, *chi* lo carica (il runtime in automatico, oppure il modello solo se decide di aprire il file), *quando* e *quanto costa a ogni sessione*.

Fonti usate, solo primarie:

- Claude Code: documentazione ufficiale su `code.claude.com/docs/en/...` (versione corrente al 2026-10-08, che cita Claude Code fino a v2.1.285).
- Codex: documentazione ufficiale. Gli URL `developers.openai.com/codex/...` indicati nel ticket ora fanno redirect 308 a `learn.chatgpt.com/docs/...`; qui si citano gli URL di destinazione.
- Codex, codice sorgente: `openai/codex`, commit `8c818cbed4bc83d30f5d515674b809646fe2676d` (HEAD di `main` al 2026-10-08). I permalink puntano a quel commit. Il codice di `main` può essere più recente dell'ultima release installata.
- Spec: [agents.md](https://agents.md/) e [Agent Skills specification](https://agentskills.io/specification).

Convenzioni: **[doc]** = affermato dalla documentazione ufficiale; **[src]** = letto nel codice sorgente; **[inferito]** = dedotto, non scritto da nessuna parte. Nessun comportamento è stato verificato eseguendo gli agenti.

## Risposte alle domande del ticket

### 1. File globali caricati in automatico

**Claude Code**
- `~/.claude/CLAUDE.md` e `~/.claude/rules/*.md`, all'avvio, in ogni progetto. [doc] [memory#choose-where-to-put-claude-md-files](https://code.claude.com/docs/en/memory#choose-where-to-put-claude-md-files), [memory#user-level-rules](https://code.claude.com/docs/en/memory#user-level-rules)
- In più c'è il CLAUDE.md gestito a livello di organizzazione (`/Library/Application Support/ClaudeCode/CLAUDE.md` su macOS, `/etc/claude-code/CLAUDE.md` su Linux) oppure la chiave `claudeMd` in `managed-settings.json`. [doc] stessa pagina, [memory#deploy-organization-wide-claude-md](https://code.claude.com/docs/en/memory#deploy-organization-wide-claude-md)
- La documentazione di memory non cita un `~/.claude/AGENTS.md` utente. **Però**: Claude Code legge `AGENTS.md` e `.claude/AGENTS.md` "in your working directory and the directories above it" quando non trova nessun CLAUDE.md di progetto, e `~/.claude/CLAUDE.md` "non conta" per questo controllo. [doc] [memory#when-claude-code-reads-agents-md](https://code.claude.com/docs/en/memory#when-claude-code-reads-agents-md). Ne segue che, per qualunque progetto sotto `~` senza CLAUDE.md, `~/AGENTS.md` e `~/.claude/AGENTS.md` (il `.claude/AGENTS.md` della directory `~`) vengono caricati come istruzioni "di progetto", **in aggiunta** a `~/.claude/CLAUDE.md`. [inferito dalla doc]. Osservazione incidentale (non è un test): nel contesto di questa stessa sessione, lanciata in un worktree di `Skills` che non ha CLAUDE.md, compaiono `/Users/luca/AGENTS.md` e `/Users/luca/.claude/AGENTS.md` come "project instructions" accanto a `~/.claude/CLAUDE.md`, e i tre file hanno contenuto quasi identico. È un costo triplicato a ogni sessione.
- `~/.agents/`: **non letto**. La doc dice esplicitamente "Not read: `AGENTS.local.md`, `AGENTS.override.md`, or anything under a `.agents/` directory". Le skill personali stanno in `~/.claude/skills/`, non in `~/.agents/skills/`. [doc] [memory#when-claude-code-reads-agents-md](https://code.claude.com/docs/en/memory#when-claude-code-reads-agents-md), [skills#where-skills-live](https://code.claude.com/docs/en/skills#where-skills-live)

**Codex**
- `$CODEX_HOME/AGENTS.override.md` se esiste e non è vuoto, altrimenti `$CODEX_HOME/AGENTS.md`; `CODEX_HOME` vale `~/.codex` per default. Viene usato un solo file. [doc] [agents-md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [src] [codex-home/src/instructions/mod.rs#L43](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/codex-home/src/instructions/mod.rs#L43) (prova `AGENTS.override.md`, poi `AGENTS.md`, e ritorna al primo non vuoto).
- A livello globale i `project_doc_fallback_filenames` **non** si applicano: il loader globale prova solo quei due nomi. [src] stesso file.
- `~/.agents/`: Codex legge `$HOME/.agents/skills` (skill utente), **non** un file di istruzioni in `~/.agents/`. [doc] [build-skills#where-codex-loads-local-skills](https://learn.chatgpt.com/docs/build-skills)

### 2. File di progetto: root, sottodirectory, AGENTS.md vs CLAUDE.md, precedenza, override

**Claude Code**
- **Avvio:** carica `CLAUDE.md`, `.claude/CLAUDE.md` e `CLAUDE.local.md` dalla cwd e da **tutte** le directory sopra di essa. Non si ferma alla root del repo. I file vengono concatenati, non si sovrascrivono: si va dalla root del filesystem verso la cwd, e in ogni directory `CLAUDE.local.md` viene dopo `CLAUDE.md`. Quindi il file più vicino alla cwd è l'ultimo che Claude legge. [doc] [memory#how-claude-md-files-load](https://code.claude.com/docs/en/memory#how-claude-md-files-load)
- **Sottodirectory:** i `CLAUDE.md` / `CLAUDE.local.md` sotto la cwd vengono caricati "when Claude uses the Read, Write, or Edit tool on a file in those subdirectories". Se Claude ha già letto quel CLAUDE.md direttamente, il runtime non lo inietta una seconda volta. [doc] stessa sezione
- **Legge AGENTS.md? Sì, dalla v2.1.277**, tramite il plugin built-in `cc-plugin-agents-md@builtin`. Con il default `claude-md-or-agents-md` legge gli `AGENTS.md` **solo se** non trova nessun `CLAUDE.md`, `.claude/CLAUDE.md` o `CLAUDE.local.md` nella cwd o sopra. `~/.claude/CLAUDE.md`, il CLAUDE.md gestito e `.claude/rules/` non contano per questo controllo. Gli altri valori sono `claude-md-and-agents-md` (entrambi: prima il CLAUDE.md, poi l'AGENTS.md di ogni directory, senza doppioni), `claude-md` e `managed-only`. Si impostano con `/config` → **Project instructions**, oppure con `pluginConfigs` in `~/.claude/settings.json`; nei settings di progetto la chiave viene ignorata. [doc] [memory#agents-md](https://code.claude.com/docs/en/memory#agents-md), [memory#choose-which-instruction-files-load](https://code.claude.com/docs/en/memory#choose-which-instruction-files-load)
- Un `AGENTS.md` in sottodirectory viene caricato quando Claude apre un file lì **con il tool Read** e quella sottodirectory non ha un proprio CLAUDE.md. Per Write/Edit la doc non lo dice, a differenza di CLAUDE.md. [doc] [memory#when-claude-code-reads-agents-md](https://code.claude.com/docs/en/memory#when-claude-code-reads-agents-md)
- `AGENTS.override.md` e `AGENTS.local.md`: **non letti**. [doc] stessa sezione
- Un `CLAUDE.local.md` conta come CLAUDE.md: aggiungerne uno in un repo che si appoggia solo ad `AGENTS.md` fa smettere Claude di leggere `AGENTS.md`. [doc] stessa sezione, nota

**Codex**
- **Avvio:** trova la project root risalendo dalla cwd fino a un marker (`project_root_markers`, default `[".git"]`). Poi scende dalla root alla cwd e in ogni directory prende il primo file che esiste tra `AGENTS.override.md`, `AGENTS.md` e i `project_doc_fallback_filenames`, al massimo uno per directory. Concatena dalla root verso la cwd, quindi il file più vicino alla cwd viene dopo e prevale. Se non trova una root, guarda solo la cwd. Non risale oltre la root. [doc] [agents-md#how-codex-discovers-guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [config-advanced](https://learn.chatgpt.com/docs/config-file/config-advanced); [src] [agents_md.rs#L1-L18](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L1-L18), [L189-L296](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L189-L296)
- **Sottodirectory sotto la cwd:** il runtime **non** le carica mai ("Codex stops searching once it reaches your current directory"). Il prompt base contiene però questa istruzione per il modello: "When working in a subdirectory of CWD, or a directory outside the CWD, check for any AGENTS.md files that may be applicable". Il caricamento è quindi su richiesta, ma lo decide il modello, non il runtime. [doc] [agents-md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [src] [models-manager/prompt.md#L27](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/models-manager/prompt.md#L27). Attenzione: il prompt specifico `gpt-5.2-codex_prompt.md` non nomina AGENTS.md, quindi questa istruzione dipende dal modello in uso (vedi "Incerto").
- **Override:** `AGENTS.override.md` sostituisce `AGENTS.md` **nella stessa directory** (l'`AGENTS.md` accanto viene ignorato) e vale anche a livello globale. [doc] [agents-md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **Legge CLAUDE.md? No, non per default.** Si può aggiungere `CLAUDE.md` a `project_doc_fallback_filenames`, ma viene usato solo nelle directory dove non c'è `AGENTS.override.md` né `AGENTS.md`. Le voci devono essere nomi di file semplici: quelle con `/` vengono scartate, quindi `.claude/CLAUDE.md` non si può configurare. [doc] [agents-md#customize-fallback-filenames](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [src] [agents_md.rs#L272-L296](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L272-L296)
- Ordine finale nel prompt: prima le istruzioni globali, poi il separatore `--- project-doc ---`, poi i file di progetto dalla root alla cwd. [src] [agents_md.rs#L47-L49](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L47-L49), [L386-L419](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L386-L419)

### 3. Import `@path` in Claude Code

- **Caricato subito, all'avvio.** "Imported files are expanded and loaded into context at launch alongside the CLAUDE.md that references them." La doc lo ripete due volte come avvertimento: gli import aiutano a organizzare, ma **non riducono il costo**. [doc] [memory#import-additional-files](https://code.claude.com/docs/en/memory#import-additional-files), [memory#my-claude-md-is-too-large](https://code.claude.com/docs/en/memory#my-claude-md-is-too-large)
- Un import dentro un CLAUDE.md di sottodirectory presumibilmente si espande quando quel CLAUDE.md viene caricato su richiesta, non all'avvio. [inferito, non documentato]
- **Percorsi:** sono ammessi sia relativi sia assoluti. I relativi si risolvono rispetto al file che contiene l'import, non rispetto alla cwd. `~` è ammesso (esempio ufficiale `@~/.claude/my-project-instructions.md`). Gli spazi si scrivono con il backslash (`Design\ Docs`); un percorso tra virgolette non viene importato. Dentro code span e blocchi di codice l'import non viene espanso. [doc] stessa sezione
- **Profondità massima:** 4 hop ricorsivi. [doc] stessa sezione
- **Import esterni:** un import in un file di progetto che punta fuori dalla cwd richiede approvazione con un dialog, una volta per progetto. Se l'utente rifiuta, l'import resta disattivato. Negli import dai file utente (`~/.claude/CLAUDE.md`, `~/.claude/rules/`) il dialog non compare (eccezione: le sessioni Cowork). [doc] stessa sezione, riquadro Warning
- Gli `@path` dentro un `AGENTS.md` letto direttamente vengono espansi anche loro. [doc] [memory#when-claude-code-reads-agents-md](https://code.claude.com/docs/en/memory#when-claude-code-reads-agents-md)
- **Codex non ha un equivalente.** La doc non lo menziona e il loader legge i byte del file e li concatena così come sono, senza fare parsing di `@`. [src] [agents_md.rs#L145-L180](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L145-L180) [inferito per assenza di meccanismo]

### 4. Link markdown semplici `[x](docs/x.md)`

Confermato per entrambi, ma come **inferenza**: nessuna delle due documentazioni dice "i link markdown non vengono seguiti".

- **Claude Code:** l'unica sintassi che il runtime espande è `@path` fuori dai backtick. [doc] [memory#import-additional-files](https://code.claude.com/docs/en/memory#import-additional-files). La prova più vicina è la frase della doc sui vecchi workaround: "A `CLAUDE.md` that tells Claude in words to read `AGENTS.md`: Claude sees `AGENTS.md` only if it decides to open the file." [doc] [memory#remove-an-earlier-agents-md-workaround](https://code.claude.com/docs/en/memory#remove-an-earlier-agents-md-workaround). Un link `[x](docs/x.md)` è nello stesso caso: il file entra in contesto solo se il modello decide di aprirlo. [inferito per assenza di meccanismo]
- **Codex:** il loader concatena il testo e basta. [src] [agents_md.rs#L145-L180](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L145-L180) [inferito per assenza di meccanismo]
- La spec Agent Skills raccomanda proprio i link relativi (`See [the reference guide](references/REFERENCE.md)`) come veicolo di progressive disclosure: le risorse vengono caricate "only when required". [doc] [agentskills.io/specification](https://agentskills.io/specification)

Conseguenza pratica: per un file che deve costare zero finché non serve, il link semplice è la scelta giusta in entrambi gli agenti. `@path` in Claude Code fa l'opposto, perché il file si paga a ogni sessione.

### 5. `.claude/rules/*.md` con frontmatter `paths:`

**Claude Code: esiste.** [doc] [memory#organize-rules-with-claude/rules/](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/), [memory#path-specific-rules](https://code.claude.com/docs/en/memory#path-specific-rules)
- `.claude/rules/` viene scansionata ricorsivamente (sono ammesse sottocartelle). Esiste anche il livello utente `~/.claude/rules/`.
- **Senza `paths:`:** la regola viene caricata all'avvio, con la stessa priorità di `.claude/CLAUDE.md`.
- **Con `paths:`:** la regola viene caricata quando Claude usa Read, Write o Edit su un file che corrisponde a uno dei glob, non a ogni uso di un tool. `paths` è una lista YAML o una stringa separata da virgole; le graffe sono supportate (`src/**/*.{ts,tsx}`) entro un budget di 1.000 pattern espansi. `paths` è l'unico campo di frontmatter che Claude Code legge. Se lo YAML non è valido, la regola viene caricata come se non avesse `paths` (quindi all'avvio, con costo pieno). Il terminale mostra solo una riga `Loaded .claude/rules/...`.
- **Compaction:** le regole con `paths:` stanno nella cronologia dei messaggi, quindi `/compact` le riassume e si ricaricano alla prossima corrispondenza. [doc] [context-window#what-survives-compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction)
- **Symlink:** sono supportati. Un symlink che punta fuori dalla cwd viene trattato come un import esterno (serve l'approvazione), e dopo l'approvazione si caricano **solo le regole senza `paths`**. [doc] [memory#share-rules-across-projects-with-symlinks](https://code.claude.com/docs/en/memory#share-rules-across-projects-with-symlinks)
- Anche le skill accettano un campo `paths` con lo stesso formato: la skill si attiva in automatico solo sui file corrispondenti. [doc] [skills#frontmatter-reference](https://code.claude.com/docs/en/skills#frontmatter-reference)

**Codex: niente di equivalente.** Le "rules" di Codex sono file `.rules` sotto `rules/` (es. `~/.codex/rules/default.rules`) che stabiliscono quali comandi Codex può eseguire fuori dalla sandbox. Sono regole di permesso, non istruzioni con ambito per percorso. [doc] [agent-configuration/rules](https://learn.chatgpt.com/docs/agent-configuration/rules). L'unico meccanismo di Codex che dipende dal percorso è la gerarchia degli `AGENTS.md` per directory (domanda 2).

### 6. Symlink `AGENTS.md` ↔ `CLAUDE.md`

**Claude Code**
- `CLAUDE.md` → `AGENTS.md` (`ln -s AGENTS.md CLAUDE.md`) è documentato e funziona; il contenuto viene letto una volta sola, anche con `claude-md-and-agents-md`. Due limiti: Edit e Write rifiutano di scrivere attraverso il symlink e rimandano al file di destinazione; su Windows i symlink sono fragili (Git li estrae come file di testo se `core.symlinks` è disattivato), e lì la doc consiglia l'import `@AGENTS.md`. [doc] [memory#share-one-file-with-other-coding-tools](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools), [memory#remove-an-earlier-agents-md-workaround](https://code.claude.com/docs/en/memory#remove-an-earlier-agents-md-workaround)
- `AGENTS.md` → `CLAUDE.md` (direzione inversa): non documentato. Con il default, siccome `CLAUDE.md` esiste, Claude legge solo quello e l'`AGENTS.md` viene ignorato, quindi nessun doppione. [inferito]. Con `claude-md-and-agents-md` la deduplica è documentata solo per un AGENTS.md che "your CLAUDE.md imports or symlinks to"; la direzione inversa non è coperta. [non documentato]

**Codex**
- Il codice di discovery dice "Symlinks are allowed" e accetta un candidato se i suoi metadati dicono "file". [src] [agents_md.rs#L189-L197](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L189-L197), [L250-L254](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L250-L254). Il loader globale usa `tokio::fs::metadata`, che segue i symlink. [src] [codex-home/src/instructions/mod.rs#L45](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/codex-home/src/instructions/mod.rs#L45)
- Quindi `AGENTS.md` → `CLAUDE.md` funziona: Codex legge il contenuto di CLAUDE.md attraverso il link. `CLAUDE.md` → `AGENTS.md` funziona anche, nel senso che Codex legge l'AGENTS.md reale e ignora CLAUDE.md. [inferito dal codice]
- La spec agents.md suggerisce lo stesso schema (`ln -s AGENTS.md AGENT.md`) per compatibilità all'indietro. [doc] [agents.md FAQ](https://agents.md/)

### 7. Limiti di dimensione

**Claude Code**
- Un CLAUDE.md fino a **4 MiB** viene caricato per intero; oltre viene **saltato** (non troncato). [doc] [memory#how-it-works](https://code.claude.com/docs/en/memory#how-it-works), [memory#my-claude-md-is-too-large](https://code.claude.com/docs/en/memory#my-claude-md-is-too-large)
- Raccomandazione: sotto le 200 righe per file. Se un file supera "the recommended length" compare un avviso all'avvio e in `/status`. Un secondo avviso compare se i file, ciascuno entro la soglia, superano insieme "a combined limit". Ogni CLAUDE.md, file di regole e import `@path` conta come file separato. **Le due soglie numeriche non sono documentate.** [doc] [memory#my-claude-md-is-too-large](https://code.claude.com/docs/en/memory#my-claude-md-is-too-large)
- `MEMORY.md` (auto memory): vengono caricate le prime 200 righe o i primi 25 KB, il limite che arriva prima; il resto viene scartato. [doc] [memory#how-it-works](https://code.claude.com/docs/en/memory#how-it-works)
- Skill: 1.536 caratteri per voce nell'elenco; elenco totale entro l'1% della context window. Dopo la compaction le skill invocate vengono riattaccate fino a 5.000 token ciascuna, con un budget complessivo di 25.000 token. [doc] [skills#skill-content-lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle)

**Codex**
- `project_doc_max_bytes`: default **32 KiB** (`32 * 1024` byte). [doc] [agents-md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [src] [config_toml.rs#L75](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/config/src/config_toml.rs#L75)
- **Il limite è complessivo, non per file.** Il codice parte da `remaining = project_doc_max_bytes` e scala i byte di ogni file man mano che lo aggiunge; quando il budget finisce, il file corrente viene troncato e i successivi (quelli più vicini alla cwd, cioè i più specifici) vengono **saltati**. [src] [agents_md.rs#L68-L95](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L68-L95), [L142-L180](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L142-L180). La guida AGENTS.md concorda ("stops adding files once the combined size reaches the limit"). La pagina config-advanced invece dice "how much to read from each AGENTS.md file", e su questo punto la doc è incoerente: il codice dà ragione a "combined". [doc] [config-advanced#project-instructions-discovery](https://learn.chatgpt.com/docs/config-file/config-advanced)
- Il troncamento produce solo un `tracing::warn!` ("project doc exceeds remaining budget; truncating"), cioè una riga di log, non un avviso a schermo. [src] [agents_md.rs#L160-L166](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L160-L166). Che il messaggio arrivi o no all'utente nella TUI non risulta da quanto letto. [inferito]
- Il troncamento lavora sui byte e poi converte con `String::from_utf8_lossy`: un taglio a metà di un carattere multibyte diventa un carattere di sostituzione. [src] stesse righe
- Il file globale `~/.codex/AGENTS.md` **non** rientra in `project_doc_max_bytes` (il budget viene applicato solo alla discovery di progetto). [src] [agents_md.rs#L58-L68](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md.rs#L58-L68)
- Le "thread instructions" fornite dall'host hanno un tetto separato di 10.000 token stimati; oltre quel tetto vengono rifiutate, non troncate. Non riguarda i file AGENTS.md. [src] [agents_md_manager.rs#L187-L199](https://github.com/openai/codex/blob/8c818cbed4bc83d30f5d515674b809646fe2676d/codex-rs/core/src/agents_md_manager.rs#L187-L199)

### 8. Skill come veicolo di contenuto caricato su richiesta

In entrambi gli agenti, a ogni sessione si paga solo la riga di catalogo della skill; il corpo di `SKILL.md` entra in contesto solo quando la skill viene usata, e i file di supporto solo se il modello li legge.

**Claude Code**
- Costo per sessione: `description` + `when_to_use` per ogni skill invocabile dal modello, troncati a **1.536 caratteri** per voce (configurabile con `skillListingMaxDescChars`). Il catalogo intero ha un budget pari all'**1% della context window** (`skillListingBudgetFraction`, oppure `SLASH_COMMAND_TOOL_CHAR_BUDGET` per un numero fisso di caratteri). Se il budget non basta, le descrizioni delle skill usate meno vengono tolte, ma i nomi restano. [doc] [skills#frontmatter-reference](https://code.claude.com/docs/en/skills#frontmatter-reference), [skills#skill-descriptions-are-cut-short](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short)
- `disable-model-invocation: true` → la descrizione **non** entra in contesto, quindi costo 0 finché l'utente non lancia `/nome`. `skillOverrides` con `"name-only"` mette in catalogo solo il nome. [doc] [skills#control-who-invokes-a-skill](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)
- Dopo l'invocazione il corpo resta in contesto per tutta la sessione ("every line is a recurring token cost"). [doc] [skills#skill-content-lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle)
- Eccezione: i subagent con skill precaricate ricevono il contenuto completo all'avvio. [doc] [skills#control-who-invokes-a-skill](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill), nota
- Le skill in `.claude/skills/` di sottodirectory si caricano (anche nel catalogo) solo la prima volta che Claude legge o modifica un file in quella sottodirectory. [doc] [skills#discovery-from-parent-and-nested-directories](https://code.claude.com/docs/en/skills#discovery-from-parent-and-nested-directories)
- `/skill-doctor` mostra il costo di ogni skill. [doc] [skills](https://code.claude.com/docs/en/skills)

**Codex**
- Costo per sessione: `name` + `description` + **percorso del file** di ogni skill. Il catalogo ha un budget pari al **2% della context window**, oppure 8.000 caratteri se la window non è nota. Se il budget non basta, Codex accorcia prima le descrizioni e poi può omettere skill, mostrando un avviso. `skills.max_context_tokens` permette di cambiare il budget, con un tetto di 10.000 token. [doc] [build-skills](https://learn.chatgpt.com/docs/build-skills), [config-reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Posizioni: `.agents/skills` in ogni directory dalla cwd fino alla root del repo, poi `$HOME/.agents/skills`, `/etc/codex/skills` e le skill di sistema. I symlink vengono seguiti. [doc] [build-skills#where-codex-loads-local-skills](https://learn.chatgpt.com/docs/build-skills)

**Spec comune (agentskills.io):** `description` al massimo 1.024 caratteri, `name` al massimo 64. Il costo stimato dei metadati è "~100 tokens" per skill; si raccomanda un corpo sotto i 5.000 token / 500 righe e risorse caricate "only when required". [doc] [agentskills.io/specification](https://agentskills.io/specification). Il limite di Claude Code (1.536) è più largo di quello della spec (1.024): una descrizione che rispetta la spec sta in entrambi.
